# Committor-guided spawning

This page documents the committor-guided spawning implementation added to
Trails-MD. It is written as a technical source for building a presentation slide
deck: the first sections give slide-ready messages, while the later sections
give implementation details and reproducibility pointers.

## One-slide summary

**Goal.** Use the committor estimated from already completed short unbiased
trajectory bursts to decide where the next adaptive walkers should start.

**Key design choice.** `spawn_scheme: committor` does not switch as soon as the
target is first found. It begins as ordinary density exploration, waits until
source-to-target support and local-stitch connectivity have stabilized, and only
then uses committor-based acquisition.

**Acquisition signal.** Cells receive high spawning priority when they are:

- near the transition region, `q ~= 0.5`;
- under-sampled;
- on the frontier between solved and unresolved local-stitch support;
- locally non-Markovian by transition-subset diagnostics.

**Current validation.** On Muller-Brown, the static local-stitch estimator agrees
with the PDE/KBE reference when the grid is sufficiently sampled. In closed-loop
adaptive tests, the 18x18 long run improves penalized RMSE over uniform sampling,
while the 24x24 run is essentially tied at the same shot budget. On explicit-water
AlaD alphaL, the method runs on CUDA and produces a connected local-stitch/MSM/KBE
comparison pipeline, but the finite-data graph still contains unresolved bins.

## Slide outline

### Slide 1: Problem

- Adaptive MD discovers rare states efficiently, but plain density spawning does
  not know which discovered states are mechanistically important.
- The committor, `q(x) = P_x(hit B before A)`, is the natural reaction-coordinate
  diagnostic.
- Brute-force committor shooting from many states is too expensive for the normal
  adaptive loop.

### Slide 2: Core idea

- Reuse the short unbiased trajectory bursts already generated by Trails-MD.
- Convert observed trajectory segments into local first-exit counts on a 2-D CV
  grid.
- Solve a stitched committor on the observed support.
- Use this committor as an acquisition function for future spawning.

### Slide 3: Why a convergence gate is needed

- First target discovery is not enough: the trajectory graph may still be sparse
  or disconnected.
- Local stitching is post-processing, but it can only solve bins with observed
  first-exit paths connected to source or target.
- The spawner therefore remains in density exploration until support metrics
  plateau.

### Slide 4: Gate metrics

The gate tracks:

- current iteration;
- number of observed non-boundary grid states;
- number of finite-q non-boundary states;
- number of isolated local-stitch states;
- number of target hits.

The gate opens only when:

- `iteration >= committor_min_iteration`;
- `target_hits >= committor_min_target_hits`;
- over the patience window, observed-state growth, finite-q growth, and isolated
  state drop are below configured thresholds.

### Slide 5: Acquisition score

For every grid cell, the implementation computes:

```text
score =
    w_transition    * 4 q (1 - q)
  + w_undersampling * 1 / sqrt(N + 1)
  + w_frontier      * frontier_bonus
  + w_markov        * markov_pressure
```

Boundary cells are excluded. Cells below `committor_min_count` are ineligible.
The Markov pressure term is ignored until `committor_markov_min_count` observations
exist in the cell, which avoids over-reacting to very sparse diagnostics.

### Slide 6: Validation status

- Static Muller-Brown estimator: local stitch RMSE vs PDE is about 0.04 on an
  18x18 grid and about 0.03 on a 40x40 grid with no isolated states.
- Closed-loop Muller-Brown, 18x18, 100 iterations: committor-guided RMSE 0.1233
  vs uniform RMSE 0.1884.
- Closed-loop Muller-Brown, 24x24, 100 iterations: committor-guided RMSE 0.2691
  vs uniform RMSE 0.2701, effectively tied at the same budget.
- AlaD alphaL explicit water, 36x36: 98,560 frames, 8,279 target hits,
  committor switch at iteration 151, local-stitch/KBE probe RMSE 0.0749.

### Slide 7: Interpretation

- The estimator is valid when the local first-exit graph is sampled and connected.
- The adaptive method is budget-sensitive: at higher resolution, the same number
  of shots covers each cell less thoroughly.
- The method should currently be presented as a plausible and implemented
  committor-guided acquisition strategy, not as a fully optimized universal
  sampler.

## Algorithmic details

### Local first-exit stitching

The grid defines discrete states in the 2-D collective-variable space. For each
observed trajectory segment:

1. Assign each frame to the nearest grid cell.
2. For a residence in a non-basin cell `i`, find the first later frame that
   reaches basin A, reaches basin B, or exits to another grid cell `j`.
3. Add a count to `C[i, A]`, `C[i, B]`, or `C[i, j]`.
4. Row-normalize the observed support to obtain a local transition matrix.
5. Solve the backward committor equation on connected interior states:

```text
q_i = P(i -> B) + sum_j P(i -> j) q_j
q_A = 0
q_B = 1
```

States without observed data or without an observed route to a boundary remain
isolated and receive `NaN` committor values.

### Spawner lifecycle

`CommittorSpawner.sample(...)` follows this sequence:

1. Pool the current projections and previous iteration projections.
2. Split pooled projections back into trajectory segments.
3. Build local first-exit counts from observed segments.
4. Solve the local-stitch committor.
5. Update gate metrics.
6. If the gate is closed, delegate to `DensitySpawner`.
7. If the gate opens, compute acquisition scores.
8. Pick frames from high-scoring cells, either deterministically by ranked cells
   or probabilistically by score.
9. If no scored frames are available, fall back to density spawning.

This keeps the method robust early in a run, when the local-stitch graph is not
yet informative.

### Why it is still dependent on adaptive exploration

Local stitching is a post-processing calculation, but it is not independent of
the sampling policy. The input graph is made from observed first exits. If
adaptive exploration has not visited a region, or has visited it without
connecting first exits to source or target, the stitched committor cannot solve
that region. Therefore:

- the same stitching code can produce different finite-data committors from
  different exploration histories;
- disconnected bins are a sampling/support problem, not a linear-solver bug;
- convergence-gated spawning is used to avoid acting on the committor before the
  observed graph is mature enough.

## Configuration

Minimal use:

```yaml
spawning:
  spawn_scheme: committor
  search_mode: explore
  spawn_type: hard
  walker: 16
  step: 1000
  committor_grid_size: 36
  committor_source: [[source_x_min, source_x_max], [source_y_min, source_y_max]]
  committor_target: [[target_x_min, target_x_max], [target_y_min, target_y_max]]
  committor_min_iteration: 100
  committor_patience: 5
  committor_min_target_hits: 1000
```

```yaml
  committor_min_iteration: 100
  committor_patience: 5
  committor_min_target_hits: 1000
  committor_max_new_observed: 2
  committor_max_new_finite: 2
  committor_max_isolated_drop: 2
  committor_weight_transition: 1.0
  committor_weight_undersampling: 0.5
  committor_weight_frontier: 0.5
  committor_weight_markov: 0.25
```

### Main parameters

| Parameter | Meaning |
|---|---|
| `committor_grid_size` | Square grid size used for local-stitch committor estimation unless `n_bins` supplies both dimensions. |
| `committor_source` | Source basin box in the first two CV dimensions. If omitted, a box is created around the first observed point. |
| `committor_target` | Target basin box in the first two CV dimensions. Required for committor spawning to activate. |
| `committor_min_iteration` | Earliest iteration where the gate is allowed to open. |
| `committor_patience` | Number of consecutive stable support intervals required before switching. |
| `committor_min_target_hits` | Minimum cumulative target hits before switching. |
| `committor_max_new_observed` | Maximum allowed observed-state growth per gate interval. |
| `committor_max_new_finite` | Maximum allowed finite-q-state growth per gate interval. |
| `committor_max_isolated_drop` | Maximum allowed isolated-state decrease per gate interval. |
| `committor_min_count` | Minimum observed count required for a cell to be eligible for spawning. |
| `committor_markov_min_count` | Minimum observations before Markov diagnostics contribute to acquisition. |
| `committor_weight_*` | Weights for transition, undersampling, frontier, and Markov terms. |

## Tests

Run the targeted tests with:

```bash
pytest tests/test_committor_spawner.py tests/test_committor_acquisition.py -q
```

Covered behavior:

- config accepts `spawn_scheme: committor`;
- `CommittorSpawner` is registered with `SpawnerFactory`;
- the spawner uses density fallback before the gate opens;
- the spawner switches after gate criteria are satisfied;
- current projections are split correctly by the number of current walkers;
- acquisition prioritizes low-count transition cells over dense or basin cells.

## Current limitations

- The implementation assumes the committor is computed in the first two projected
  CV dimensions.
- The local-stitch graph is finite-data dependent; sparse adaptive histories can
  leave isolated bins.
- The Markov diagnostics are acquisition diagnostics, not proof that the adaptive
  data are kinetically unbiased.
- The toy acquisition weights are plausible but not globally optimized.
- `spawn_scheme: committor` is an exploration strategy. It should not be used to
  estimate physical rates directly; use weighted ensemble kinetics or an MSM for
  rate estimation.

## Suggested narrative

The implementation is best presented as a two-stage adaptive strategy:

1. Use fast density exploration to discover source-target support and populate
   the local first-exit graph.
2. After support converges, use the observed local-stitch committor to concentrate
   new unbiased bursts near the transition region and unresolved frontier.

This directly addresses the main failure mode seen earlier: switching on the
first target hit can produce a disconnected or poorly conditioned local-stitch
problem. The convergence gate makes the committor a refinement signal after the
exploration phase has generated enough graph support.
